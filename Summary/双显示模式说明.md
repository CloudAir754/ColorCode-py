# 双显示模式说明（record / measure）

本文对应服务端分支 `feat/two-display-modes` 与 Android 同名分支，说明结果弹窗的两种显示方式、内存记录、速度计算和伪输出方法。

## 1. 两种模式一览

| 模式 | 触发条件 | 弹窗用途 |
|---|---|---|
| `record`（记录） | 某个 3×3 颜色矩阵第一次完整识别到三个阶段 | 记录 `T1`、`T2` 与 `ΔT1`、`ΔT2` |
| `measure`（测量） | 同一颜色矩阵在当前服务进程内再次识别 | 用已存 `ΔT` 回取拉伸比，显示 `α0/α1/α2` 和速度 |

模式由服务端自动判断，手机端不需要切换。判断依据是 `FlaskServer/video_processor.py` 中的时间缓存是否命中：

- 缓存未命中：本次视频自己识别三个阶段 → `record`，同时把时间写入内存；
- 缓存命中：使用第一次记录的时间，在当前视频对应时刻取拉伸比 → `measure`。

## 2. record：第一次记录变色时间

### 2.1 弹窗样例

```text
Image infomation:
Details:
T0: 0s RGB
T1: 1.50s RG
T2: 2.50s G
ΔT1=1.50；ΔT2=2.50；
```

### 2.2 时间定义

```text
T0 = 0 s            RGB 阶段
T1 = RGB → RG 的时长
T2 = RG  → G  的时长
ΔT1 = T1
ΔT2 = T2
总时长 = ΔT1 + ΔT2
```

也就是说，`T1`/`T2` 表示相邻阶段之间的时长，而不是从 0 开始累加的绝对时间。弹窗按约定显示 `T1`、`T2`；如果实验记录需要“G 的累计时间”，它等于 `T1 + T2`。

### 2.3 内存记录的到底是什么

服务端 `SAMPLE_TRANSITION_TIME_CACHE` 以 3×3 颜色矩阵为键，保存第一次识别到的阶段相对偏移：

```python
{
    (("Green", "Red", "Blue"), (...), (...)): {
        1: 0.0,      # T0
        2: 1.5,      # T1
        3: 4.0,      # T1 + T2
    }
}
```

这些值只存在 Python 进程内存中。关闭或重启服务后缓存清空，下一次识别又会从 `record` 开始。

## 3. measure：后续计算拉伸量和速度

### 3.1 弹窗样例

```text
Image infomation:
Name: 5D code42
Details:
RGB α0：100.00%
RG α1：127.00%
G α2：145.00%
ΔT1=1.50；ΔT2=2.50；（known）

Speed:
337.50 mm/min
```

### 3.2 三个拉伸百分比

`α0/α1/α2` 分别是 `RGB/RG/G` 三个阶段的拉伸比率，显示为百分数：

```text
α = 拉伸比 × 100%
拉伸比 = 1 / 平均(色块宽 / 色块高)
```

其中拉伸比来自 `ColorCodeDetector/detect_radio.py` 的 `stretch_ratio` 字段。`measure` 模式不会沿用第一次视频的拉伸比，而是用已存时间在当前视频里找最接近的帧重新取值。

### 3.3 速度公式

```text
v = (α2 - α0) / 100 × L0 ÷ (ΔT1 + ΔT2) × 60     单位：mm/min
```

- `α2 - α0`：从 RGB 到 G 的拉伸比率变化量；
- `L0`：拉伸前的材料长度（标距），单位 mm；
- `ΔT1 + ΔT2`：从 T0 到 T2 的总时长，单位 s；
- 乘 60 是把 mm/s 换算为 mm/min。

算例（与伪输出默认值一致）：

```text
α0 = 100.00% = 1.00
α1 = 127.00% = 1.27
α2 = 145.00% = 1.45
L0 = 50 mm
ΔT1 = 1.50 s，ΔT2 = 2.50 s

v = (1.45 - 1.00) × 50 ÷ (1.50 + 2.50) × 60
  = 0.45 × 50 ÷ 4.00 × 60
  = 337.50 mm/min
```

### 3.4 材料长度配置

修改：

```text
ColorCode-py\FlaskServer\experiment_config.py
```

```python
PRESET_MATERIAL_LENGTH_MM = 50.0
```

改成实际标距（mm）后重启 Flask 服务即可，Android 不需要重新安装。响应里的 `speed.material_length_mm` 会带回本次使用的长度，便于核对。

## 4. 服务端返回结构

### 4.1 record

```json
{
  "mode": "record",
  "stages": {
    "T0": {"time": 0.0, "color": "RGB"},
    "T1": {"time": 1.5, "color": "RG"},
    "T2": {"time": 2.5, "color": "G"}
  },
  "time_differences": {
    "delta_t1": 1.5,
    "delta_t2": 2.5,
    "unit": "s"
  }
}
```

### 4.2 measure

```json
{
  "mode": "measure",
  "name": "5D code42",
  "stretch_percent": {
    "alpha0": 100.0,
    "alpha1": 127.0,
    "alpha2": 145.0
  },
  "time_differences": {
    "delta_t1": 1.5,
    "delta_t2": 2.5,
    "unit": "s",
    "known": true
  },
  "speed": {
    "value": 337.5,
    "unit": "mm/min",
    "material_length_mm": 50.0
  }
}
```

### 4.3 字段说明

| 字段 | 含义 |
|---|---|
| `mode` | `record` / `measure` / `incomplete` |
| `stages.T0/T1/T2` | 阶段时长和对应颜色；`T1` 为 RGB→RG，`T2` 为 RG→G |
| `time_differences.delta_t1` | `ΔT1`，秒 |
| `time_differences.delta_t2` | `ΔT2`，秒 |
| `stretch_percent.alpha0/1/2` | 三个阶段的拉伸百分比 |
| `speed.value` | 平均速度，mm/min |
| `speed.material_length_mm` | 本次计算用的材料长度 |

`mode="incomplete"` 表示连 RGB 阶段都没识别到，`message` 为给用户看的提示。

## 5. 伪输出（不跑图像识别）

用途：只验证“上传—轮询—弹窗”或给老师演示指定结果。手机仍需上传任意可读视频，但服务端收到完整视频后会跳过 OpenCV，立即返回预设数据。

### 5.1 切换到伪输出

编辑：

```text
ColorCode-py\FlaskServer\display_test_config.py
```

```python
DISPLAY_TEST_MODE = "record"     # 演示第一种显示
# 或
DISPLAY_TEST_MODE = "measure"    # 演示第二种显示
```

保存后关闭并重新双击 `启动服务.bat`，再在 Android 上传视频、点击 **Start video analysis**。

测试结束务必改回：

```python
DISPLAY_TEST_MODE = None
```

并重启服务，否则真实视频也会返回假数据。

### 5.2 伪输出默认值

`record`：

```text
Image infomation:
Details:
T0: 0s RGB
T1: 1.50s RG
T2: 2.50s G
ΔT1=1.50；ΔT2=2.50；
```

`measure`：

```text
Image infomation:
Name: 5D code42
Details:
RGB α0：100.00%
RG α1：127.00%
G α2：145.00%
ΔT1=1.50；ΔT2=2.50；（known）

Speed:
337.50 mm/min
```

这两段文字由 `display_test_config.render_preview()` 生成，并由 `tests/test_display_test_config.py` 与 Android 端单元测试分别锁定，防止两端文案改歪。

### 5.3 可以改哪些值

`RECORD_TEST_INFO`：

- `stages.T0/T1/T2.time`：阶段时长；
- `stages.*.color`：阶段颜色标签；
- `time_differences.delta_t1/delta_t2`：弹窗中的 ΔT。

`MEASURE_TEST_INFO`：

- `name`：样品编号；
- `stretch_percent.alpha0/alpha1/alpha2`：三个百分比；
- `time_differences.delta_t1/delta_t2`：已知 ΔT；
- `speed.value` / `speed.unit`：速度显示值。

修改数值后，弹窗文字会按新值重新排版；但 `speed.value` 是直接展示的，伪输出不会自动按公式重算。需要与公式一致时，请按 3.3 节手算后填入。

### 5.4 旧模式名

为兼容旧脚本，`"initialization"` 等同 `"record"`，`"preset"` 等同 `"measure"`。

## 6. 文案改在哪里

| 位置 | 作用 |
|---|---|
| `FlaskServer/display_test_config.py` | 伪输出数值和预览文字 |
| `FlaskServer/video_processor.py` | 真实结果字段、时间缓存、速度计算 |
| `ColorCode-Andrioid/.../ResultDisplayFormatter.kt` | Android 弹窗的最终排版 |
| `ColorCode-Andrioid/.../VideoUploader.kt` | 调用排版函数、弹窗标题 |

改字段名时必须同时改两端。只改文案不需要动接口字段。

## 8. 兼容性与注意事项

1. 新服务端 + 旧 APK：旧 APK 不认识 `mode` 字段，会退回显示原始 JSON。请同时安装新 APK。
2. 新 APK + 旧服务端：`info` 中没有 `mode`，同样显示原始 JSON，便于发现服务端未更新。
3. 服务重启会清空内存时间；如果只想演示 `measure`，直接用伪输出，不必先跑一遍 `record`。
4. 同一颜色矩阵代表同一个试样。不同试样务必使用不同颜色矩阵，否则会错误复用时间。
5. 速度依赖材料长度；换材料或换标距后，先改 `PRESET_MATERIAL_LENGTH_MM` 再测。
